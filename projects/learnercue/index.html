LearnerCue

Who should coaches review first?

When coaching time is limited, the order of review matters. LearnerCue explores which still-enrolled course records could be reviewed first on a given course day. Coaches decide whether and how to offer support.

The question

Historical learning data can support a more informed weekly review. I framed a time-specific question: using only the information available by a checkpoint, which enrolled course records should a coach inspect first? The output is a ranked review list, with recorded observations to check before considering support.

My approach

I joined and inspected course, registration, assessment and activity data from the Open University Learning Analytics Dataset. I built weekly snapshots for 16 checkpoints and excluded information that would only become available later.

I compared simple references with several machine-learning models, separated people in development splits and evaluated on later course presentations. The application uses exported weekly Histogram Gradient Boosting models. Precision, recall and Average Precision make the trade-offs visible.

From the data to a coach’s next step

  1. Start the guided example. The public app opens synthetic weekly records. A prepared weekly CSV can also be uploaded.
  2. Choose a course day and course. The overview leads to the course’s complete ranked review list.
  3. Inspect a record. Review recorded activity, outstanding assignments and observations for an individual learner.
  4. Consider support. The prototype shows possible actions and a simulated review status. The coach remains responsible for any outreach.

An exploratory result

On day 27 of the 2014J course presentations, the weekly model achieved an Average Precision of 0.625, compared with 0.429 for a reference based on course and registration data.

The top roughly 20% per course included 1,006 of 2,947 later withdrawals or failures: 34.1% recall and 64.2% precision. These figures describe the historical evaluation, while the public interface uses synthetic example records.

The 2014J data were revisited during development, so these are exploratory findings rather than an untouched final test. They do not establish that coach outreach prevents withdrawal or that the model transfers to another institution.

Explore the prototype

The interface is available in English and German. It includes a course overview, the full ranked roster, observations for selected learners and a simulated review workflow. The roster can also be downloaded as a printable HTML report. The separate management view explores provisional workload assumptions.

What this project demonstrates

  • Research design. A defined question and outcome, with an explicit time boundary for the inputs.
  • Data analysis. Quality checks and weekly snapshots assembled from several related data sources.
  • Evaluation. Model and reference comparisons, later-course evaluation and explicit limits on the conclusions.
  • Communication. A bilingual application, a guided example, readable documentation and a printable course report.

Scope and documentation

LearnerCue is a completed portfolio project and an interactive prototype. The demonstration uses fabricated records, and its review status is simulated. The application sends no messages. Methods, exploratory results and development choices are documented in the repository.
